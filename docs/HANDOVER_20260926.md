## 5. 守ること（ローカルの記憶と取り決めをここに写した）

- **met は自分で立てない。** 判定は gate-verifier（`.claude/agents/gate-verifier.md`）に別コンテキストで
- **契約テストを書いたら必ず変異を当てる**（生き残ったらテストを足す）
- **`backend/.env`・`*.key`・`vault-assets/raw/**` は読まない。** 実キーの呼び出しは課金（憲法第3条）
- **承認を試すときは `--by claude-code`。** ユーザーの名前で承認しない（5周目で、私の試しの承認5本が
  ユーザーの承認に見えていた。注記は `backend/config/approval_annotations.json`）
- **経路を閉じたら、その経路に触れる既存テストを全部探して移す**（3度漏らした）。触れるテストを grep で
  集め、**HEAD と origin/main の両方で回して失敗の集合を突き合わせる**（`git worktree add` で main を展開）
- **コミットの前に台帳のゲートを必ず回す**（8周目の退行の原因）:
  `python -m backend.c4_inventory --gate` / `python -m backend.c4_response_gate --gate` /
  `python -m backend.export_sites --gate` / `python -m backend.ux_verification.ui_api_ratchet --ratchet` /
  `pytest backend/tests/test_vision_backlog_canon.py backend/tests/test_c4_inventory.py`
  （いずれも `GOOGLE_API_KEY=dummy_key_for_ci PYTHONPATH=./backend`）
- **実走はトラッキングされたファイルを書き換える**（`backend/agents/memory/*`・`backend/usage_tracker/*`・
  `backend/branding/{decision_log,constitution,design_tokens_history,evolution_log}.json`・
  `backend/quality_score_history.jsonl`・`assets/asset_index.json`）。**コミットしない・戻す**
- 罠: ヒアドキュメントの `\n` は1段食われる（`chr(92)+"n"` を組み立てる）／正典の `condition_notes` は**リスト**／
  `c4_inventory.json` は `indent=1`・正典は `indent=2`／新しいテストは `pytest.ini` の `testpaths` に登録／
  `pytest`（素）は手元で収集エラー（D-46。`--continue-on-collection-errors` を両側に）
- gate-verifier 1周のコスト: **約30万〜42万トークン・30〜90分**（8周の実測）
- エスカレは**選択肢つき**（表: 判断・大きさ・コスト・推奨 → 選択肢）。依存する判断は後の段へ

## 6. 事前承認（2026-09-26 のユーザー指示）

**「引継ぎ後のクラウドセッションは、ギフト分を使い切るまでは突き進む」。** したがってクラウドでは:

- **周回ごとの確認は要らない。** 範囲内の反証は塞ぎ、範囲外は limits に宣言して、次の周を回してよい
  （`verification_policy` の「3周目に入る前にユーザーへ」は、この指示で事前に承認されたものとして扱う）
- **止まるところ**: (a) C1〜C3 が met になって中間ゲート報告を出したとき（C5 に進むか R3 を先にするかは
  ユーザーが決める — 憲法第1条・第2条）、(b) 課金が絡むとき（実キー・外部サービス — クラウドでは起きない
  はず）、(c) 条件文そのものを変えたくなったとき（条文はユーザーと協働）、(d) クレジットが尽きそうなとき
- **クレジットが尽きる前に**: この文書の §1〜§3 を最新にし、コミットして push してから止まる
  （途中で切れると、どこまで進んだかがローカルに戻れない）
