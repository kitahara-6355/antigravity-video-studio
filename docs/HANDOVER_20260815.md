**反例**: `frontend/package-lock.json` は**走査からも外れ、ハッシュ固定もされない唯一のファイル**。
lockfile を有効な JSON のまま1キー足して JS を埋め、
`import.meta.glob('../package-lock.json', {as:'raw'})` → `JSON.parse` → `Blob` →
`URL.createObjectURL` → 変数引数の `import()` で実行すると、
**4ゲートすべて exit 0 のまま `vite build` が通り dist に `fetch('/api/tasks')` が出る。**
禁止語彙には1つも触れていない。

**原因**（`backend/ux_verification/ui_api_closure.py`）: 2つの条件がずれている。

- `_iter_files()` の除外は `rel in CLOSURE_EXCLUDED_FILES`
- `_boundary_findings()` のハッシュ収集は `path.suffix.lower() in CLOSURE_BINARY_SUFFIXES`

**直し方**: **走査から外したものは、例外なく sha256 を固定する**。
`CLOSURE_EXCLUDED_FILES` のファイルも `binary_assets` に入れる
（`CLOSURE_EXCLUDED`（`node_modules` / `dist`）はビルド生成物で CI に存在しないので対象外。
そのことは意味表に書く）。あわせて:

- `--semantics` の『確かめないこと』に「`package-lock.json` の中身は読まないが sha256 で固定する」を追加
- テストを足す（`backend/tests/test_ux_ui_api_closure.py`）:
  走査から外れたファイルは**必ず** `binary_assets` に載ること／lockfile の差し替えがラチェットで落ちること

## 3. 何を作ったか（コードを読む前にこれだけ）

**主題は「検出をやめて閉包にする」。** 散らばった呼び出しの URL を1件ずつ*正しく解決する*のは
精度を要求する仕事で、読み違いが黙って PASS になる（P4 が14回破られた原因）。
**禁止は精度を要求しない** — 誤検出しても FAIL が増えるだけで沈黙にならない。

| 場所 | 役割 |
|---|---|
| `frontend/src/gateway/endpoints.js` | 叩ける先のカタログ。**84項目・1行1項目のリテラル** |
| `frontend/src/gateway/client.js` | 実呼び出し。`apiFetch` / `apiUrl` / `apiSocket` / `openApiUrl` |
| `frontend/src/gateway/external_urls.json` | 外部 URL の許可リスト（18件） |
| `backend/ux_verification/ui_api_closure.py` | 閉包ゲート＋閉包ラチェット（**新規**） |
| `backend/ux_verification/ui_api.py` | P4 のゲート。カタログを一級の呼び出し先として突き合わせる |
| `backend/ux_verification/ui_api_ratchet.py` | P4 のラチェット。`--migrate` / `--resolve` を追加 |
| `.github/workflows/ci.yml` | 214-227 行に閉包の2ステップ（`continue-on-error` 無し） |
| `pytest.ini` | 371-373 行に3テストを登録 |

**メソッドはカタログが決める。** 呼び出し側から指定できない。
ディレクトリ名が `src/api/` ではなく **`src/gateway/`** なのは、`from '../api/client.js'` が
backend プレフィクス `/api/` を含んでしまい、禁止を素のままに保てないから。

### 繰り返している私の失敗（3型）

1. **修正が新しい沈黙を作る**（2・3・4・5・7回目）。閉包を広げる実装が別の場所を狭める
2. **綴り／部分の列挙で塞いだつもりになる**（1・5・6・7回目）。次の綴りで破られる
3. **測っていないことを『確かめること』に書く**（1・3・4・6・7回目）。
   C-4 が毎回連動して落ちる。**実装を変えたら意味表も同じコミットで直す**

### 4型目になりかけているもの

**「破られた → 塞ぐ」を無限に続ける**こと。8回やって8回破られた。
塞ぐこと自体は正しいが、**条件文が達成不能なら塞いでも終わらない**。
§1 の (2-B) を必ず読むこと。

### 効いた原則

- **禁止は精度を要求しない。** コメントも除去しない（コメント内の URL も落とす）
- **判定基準は宣言側から導く**（backend プレフィクスは EndpointRegistry から）
- **正規表現の本体まで**ベースラインに固定する。自分自身の検出器も
- **除外は「読まない場所」ではなく「読まない根拠」を固定する**
