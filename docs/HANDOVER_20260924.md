## 2. 作ったもの（どこに何があるか）

```
output/runs/<run_id>/
  run.json            実行記録（提案で awaiting_approval → 書き出しで completed/degraded に閉じ直す）
  proposal.json       提案 = 人が見て決める材料（品質・モード・プレビューの指紋・使ったモデル）
  proposal/           AI の出力の写し（変えない）
  working/            人が直す現物（ここを直すと承認の差分に出る）
  approval.json       承認（いつ・誰が・提案の指紋・人の差分・開示の判断）
  approval_history/   古くなった承認（上書きで消さない）
  export.json         書き出し（どの承認で・何を出したか）
```

## 4. 今日わかった罠（**必ず読む**）

- **`pytest`（素）は手元で collection error で止まる。** 原因は R2 と無関係で**元から**
  （`origin/main` でも同じ）。`test_ai_proofreader.py` など数個のテストが**import 時に**
  `sys.modules['google']` を MagicMock に差し替えて戻さないので、`test_routers_health.py` の
  `import faster_whisper` が名前空間パッケージを壊す。**CI は緑**（run 35409157620 の
  「Python テストスイート」）なので環境差。手元で全部回すときは
  `--continue-on-collection-errors` を付け、**両側（HEAD と origin/main）に同じ条件で付ける**。
  台帳は D-46
- **exit コードをパイプ越しに測らない。** `cmd | tail` の `$?` は `tail` のもの。
  今日いちど「`--export` が exit 0 を返す（C1 の穴）」と誤認した。実体は exit 1 だった
- **ヒアドキュメントの中の `\n` は1段食われる。** `python - <<'PY'` に書いた `"\\n"` が
  実ファイルでは生の改行になり、3回 SyntaxError を出した（うち1回は **NUL バイト**を
  テストに書き込んだ）。文字列に改行を入れたいときは `chr(92) + "n"` を組み立てる
- **JSON の台帳は書式を合わせてから書く。** `c4_inventory.json` は **indent=1**。
  2 で書き直したら 5,000 行の差分になった（`json.dumps(..., indent=1) + "\n"` が正）
- **新しいテストファイルは `pytest.ini` の `testpaths` に登録する。** R2 の4ファイルが
  登録漏れで本走に入っていなかった（`testpaths` はファイル単位の列挙）
- **行番号がずれると UI-API ラチェットが赤くなる。** 経路を消した回は
  `--redeclare "<理由>"` で受理する（呼び出し先の総数が変わっていないことを添えて）
- **実走はトラッキングされたファイルを書き換える。** `backend/agents/memory/*`・
  `backend/usage_tracker/*`・`backend/branding/decision_log.json` は**コミットしない**（D-35）
