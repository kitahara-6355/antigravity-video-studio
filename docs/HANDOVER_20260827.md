## 3. gate-verifier の指摘と対処（2周ぶん）

**1周目（旧 C1・`d18ccd5`）で 3件、2周目（新 C1b・`29f094d`）で 2件。すべて「うっかり型」。**
どれも**自分で再現してから直した**。

| # | 指摘 | 対処 |
|---|---|---|
| N-1 | **ゲートが赤い実走を落とせない。** run の `status` を一度も見ておらず、動画も全 run から集めていたので1本前の mp4 が永久に緑を作った | `check_run_status()` を新設（緑は `completed` と `degraded` だけ）。動画と `models_used` も最新1本に |
| N-2 | **一度も動かなかった工程が `completed` に化ける** | 着手した工程は結果を返すまで「落ちた」扱い。事前フックの例外も数える |
| N-3 | **再開案内が旧パイプラインを指す** | `inputs.mainline` で分岐。**本線に再開は無い**ので、やり直しの入口を出す |
| 指摘1 | **致命的失敗のとき落ちた工程が記録に残らない。** `status: failed` なのに `all_features_active: true`、`--resume` が「失敗はありません」で exit 0 | `health.failed_stages` を `_outcomes` から導く。断られた工程は `_record_dead_stage()` で記録に1件残す |
| 指摘2 | **ガバナンスが禁じた工程を改善ループが迂回して実行していた** | `_ensure_allowed()` を通す |

加えて条件文が名指ししている「**工程が結果を返さない**」（`None` 返し）も塞いだ（`_normalized()`）。

**検証者は mutation test（修正を1つずつ外す）で、追加テスト全件が空振りしていないことまで確認している。**
