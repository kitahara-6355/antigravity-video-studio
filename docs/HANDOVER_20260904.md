## 7. 踏んだ罠（実際にやらかしたもの）

- **CI の `cancel-in-progress`。** `testpaths 外の退行検知` は**1時間50分前後**。
  PR イベントでは `cancel-in-progress: true` なので、**1周ごとに push すると毎回打ち切られる**。
  **run が完走するまで push しない**
- **「呼び出し口の閉包ゲート」はコメントも検査する。**
  説明コメントに `/api/...` と書くと落ちる（`ci.yml` に明記あり）。
  **呼び出し口の名前**（`getSettings` 等）で書くこと。2026-09-04 にこれで CI を赤にした
- **gate-verifier と作業ツリーを共有している。** 検証中は**私がファイルを触らない**。
  scratchpad も共有なので、**verifier に「自分用の接頭辞を付けて」と頼む**
  （前に私の `mutate.py` を上書きされた）
- **テスト実行が状態ファイルを書き換える**（`assets/asset_index.json` /
  `backend/branding/*.json` / `backend/agents/memory/Director.json` /
  `backend/quality_score_history.jsonl` / `backend/tests/e2e_results.json` /
  `backend/usage_tracker/usage_data.json` / `archives/analytics/history.jsonl` /
  `src/scenes_data.json` / `backend/data/reviews/`）。`-encoders` と
  `backend/test_previews_tmp/` というゴミも生える。**`git add -A` の前に1件ずつ見る**
- **同名テストの重複。** `backend/tests/` と `tests/` に同名ファイルがある。
  **片方だけ直すと CI の「testpaths 外」で落ちる**
- **`Path.write_text` は Windows で LF を CRLF に変える。** `write_bytes` を使う。
  コミット前に `.py` の CRLF を LF へ直すこと
- **Bash のヒアドキュメントはバックスラッシュを壊す。** Python の行継続 `\` を
  書くと `\\` になって構文エラーになる。**Edit ツールを使う**
- **`l` を変数名にすると ruff E741 でラチェットが落ちる**
- **手元（Windows）で緑なのに CI（Linux）で赤**になることがある

## 9. 進め方の約束

- **`met` は自分で立てない。** `gate-verifier` に別コンテキストで検証させてから。
  正典の `met` は **2箇所**（`current_phase` と `roadmap.phases["R1.5"]`）
- **gate-verifier は直列で回す**（並走させない）。**検証中は作業ツリーを触らない**
- **`verification_policy` の2周上限はとうに超えている。ユーザーが周回を承認済み**
  （2026-09-04 に「18周目を回す」を選択）。
  ただし**範囲の判断（この経路は C4 の対象か、`limits` に落とすか）はユーザーに上げる**
- 指摘が出たら、**対応してから**次の周を回す
- テストが3回連続で FAIL したら止めて報告する
- 有料利用は予算の範囲内なら都度確認不要（憲法第3条）
- **C4・C6 が揃ったら R1.5 のフェーズ終了。** 正典2箇所に met を立て、CI 緑を確認したうえで、
  ユーザーに `/gate-report` の実行を依頼して止まる（**`/gate-report` はユーザー起動専用**）

> 商品化レベルの品質基準のバランス**を重視したプランでお願いしたい。
> 判断しやすい**指標をもってエスカレ**してほしい。

→ 周回を止める／続けるの判断を仰ぐときは、**発見の大きさ（到達性・収益化判断への影響・
後から直せるか）とコスト**を表にして出す。
