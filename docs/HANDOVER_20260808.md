## 3. この作業で効いた原則（次も効く）

**`gate-verifier` は 26回中 25回当てた。** 通さずに「完了」と報告していたら
25回とも偽の緑を出していた。**必ず通す。**

### C-3 は16回作り直した。破られ方は2型しかない

1. **同じ主張が書き方の違いで強弱に振れる**
   空白(10) / 句点(11) / 読点(12) / 活用と語彙外の述語(14) / 接尾辞(18・23) /
   ハイフンとアンダースコア(19) / 大文字小文字(21)
2. **照合や免除が1箇所にしか掛かっていない**
   名前付きスロットだけ(13) / endpoint だけ(18・24) / prefix に無い(20・25) /
   未登録が fail-open(22) / 宣言キーが1つ漏れる(25)

**次に同じ層を作るときの教訓:**

- **自然言語を「検出」しようとすると必ず負ける。** 語彙を足すたびに次の未登録語で
  抜ける。**閉包**（テンプレート・辞書）に倒す
- **既定値は fail-closed に。** 「登録が無い＝無検査」「空＝無検査」
  「記録が無い＝変化なし」はすべて穴だった
- **網羅は網羅自体をテストで固定する。** 「宣言キーを全部照合している」ことを
  テストで縛らないと、キーを1つ足したときにそこだけ漏れる
- **保証の置き場所を変える手がある。** 語彙で閉じきれないと分かった時点で、
  「既存項目が黙って変わらないこと」はラチェット（`description` を
  `DECLARATION_KEYS` に入れる）に移した

**閾値を終了条件にしない。** P2 の「充足率 90% 以上」は数え方に依存する値で、
検証のたびに 68% → 89% → 86% と動いた。P3 は「対応が取れていない項目がゼロ」に
して振動を止めた。

**判定していないものを PASS にしない。** 数字は下がるが、下がった数字は本当のこと。
