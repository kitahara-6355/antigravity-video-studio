# R2 C1〜C3 の実装計画（2026-09-19）

設計: `docs/specs/2026-09-19-r2-approval-design.md`。**TDD — テストを1つ書き、通す実装を1つ書く。**
契約テストには必ず変異を当てる。テストの出力は `tmp_path` と `AVS_RUNS_DIR` に閉じる（D-29 の事故を繰り返さない）。

## 手順

| # | やること | テスト（先に書く） | 変異（落ちること） |
|---|---|---|---|
| 1 | **提案で止まる。** coordinator は改善ループの後に提案を残し、`awaiting_approval` で閉じる。書き出しの工程は呼ばない | 偽 worker の coordinator: 状態が `awaiting_approval`・`RenderWorker` が呼ばれない・`proposal.json` の欄がそろう | 書き出しを呼ぶ／状態を completed にする |
| 2 | **D-41: ループは書き出しの前。** 書き出しモードはループの後の品質で決まる | ループで合格する偽 worker → 提案の書き出しモードが production | ループを提案の後に戻す |
| 3 | **承認の記録。** `approval_gate --approve` が提案の sha256・人の差分・開示の判断を `approval.json` に残す | 写しと現物が同じ → 差分は空で承認は残る／現物を直す → 差分が入る／`--synthetic` を省く → exit 1 | 差分を取らない／開示の判断を省けてしまう |
| 4 | **書き出しの門。** 承認が無い・提案が承認の後に変わった・開示が無い、のどれでも書き出さない。門は書き出しの関数の直前 | 3つの場合それぞれ exit 1 で、書き出しの工程は失敗として記録される／そろっていれば書き出して `export.json` と `ai_disclosure` 入りのサイドカーを残す | 門を外す／照合を外す／開示の確認を外す |
| 5 | **画面経由も同じ門。** router から走らせた実走も承認待ちで止まり、承認なしでは書き出せない | router の開始 → 状態が承認待ち／書き出しを直接呼んでも門で止まる | router だけ門を通らない |
| 6 | **`--gate`** | 承認待ち → FAIL（書き出していない）／承認なしの書き出し → FAIL／開示なし → FAIL／そろっている → exit 0 | 各分岐を緑にする変異 |
| 7 | **`--trace <run_id>`**（R2-C2 の verify） | 提案 → 承認（差分・開示）→ 書き出し が出る／承認が無ければ「承認されていない」と出る | 差分を出さない |
| 8 | **R1.5 の条件を壊さない** | `artifact_gate` は承認待ちを「書き出していない」として FAIL し、理由を出す／`run_record --resume` は承認と書き出しの手順を案内する | — |
| 9 | **C4b の面** | `python -m backend.c4_response_gate --gate` を流し、形が変わったら査読して台帳を更新する | — |
| 10 | **実走** | ダミーキーと実キーで各1本、承認して書き出すまで。`--gate`・`--trace`・`artifact_gate --gate` | — |
| 11 | **limits と引継ぎ** | 議長のバイパスを作らないことを limits に宣言。引継ぎを更新 | — |
| 12 | **gate-verifier**（C1〜C3）→ **中間ゲート**の報告 | — | — |

## 影響の見積もり（2026-09-19 に数えた）

agents 側の `PipelineCoordinator.execute()` を呼んで completed や書き出しを確かめているテストが約10ファイルある
（`tests/test_pipeline_coordinator.py`・`backend/tests/test_workers/test_pipeline_coordinator.py`・
`backend/tests/test_shared/test_pipeline_coordinator*.py`・`test_agents_run_record.py`・`test_c4_quality_marks.py`・
