## §5.1 自律回復プロトコル（置き換え）

> ### 5.1 自律回復プロトコル（Self-Healing）
> **「環境トラブルは、ユーザーの認知負荷になる前に解決せよ」**
>
> エージェントは、環境の異常（起動失敗、ポート競合、依存関係の欠落等）を検知した場合、ユーザーの指示を待たず、以下を自律的に行うこと。
>
> 1.  **即時復旧**: その環境の手順書に従って復旧を図る（ローカル: `resume_dev.ps1`／クラウド: セットアップスクリプトと `docs/M0_CLOUD_SETUP_*.md`）。手順書に無い操作で直したときは手順書に足す。
> 2.  **事後報告**: 復旧完了まで確認は不要。完了後に「何が起き、どう自動対処したか」を報告する。
> 3.  **課金の例外**: 復旧のために 1 円でも課金が要る場合は自律の対象外（CLAUDE.md 憲法第3条）。

## §9.3 承認フロー（置き換え）

> ### 9.3 承認フロー
>
> ```
> 実走（提案で止まる） → プレビュー → 承認画面（工程ごとのモデル・理由・品質） → 議長承認 → 書き出し → 置き場の監査
> ```
>
> *   **承認なき書き出しの禁止**: 承認されていない提案から完成品を書き出してはならない。書き出しの門は CLI と画面で**同じ関数**（`approval_gate.approve` → `export`）。
> *   **見ていないものは承認できない**: プレビューが無い提案は承認も書き出しもできない。
> *   **証跡**: いつ・誰が・どの案を・どう直して承認したかが動画ごとに残る（`--trace`）。AI 生成の開示（合成メディアの判断）が欠けていたら書き出しは止まる。
> *   **却下時の対応**: フィードバックを記録し、該当パラメータを修正して再プレビューを行う。不満な工程は承認画面から1段上げてやり直せる。
> *   **バイパス権限は設けない**（旧条文の「緊急時のプレビューのスキップ」を削除。正典 R2 limits #3・2026-09-27 改訂）。

> ### 16.5 段階的レビュー（Progressive Review）— §9.3 の承認工程に一本化
>
> 5段階のレビューポイント（字幕・テロップ・サムネイル／画像・OP/ED・最終統合）は、**§9.3 の承認画面の工程表示**として実現する。

## §26 自律型開発ループ（置き換え）

> ## 26. 自律型開発と協調ガバナンス（human-on-the-loop）
>
> ### 26.1 目的
> 実装は **Claude Code に一本化**する（CLAUDE.md 憲法第6条）。人間はフェーズの境界だけで判断し、フェーズの中は Claude Code が自律実行して事後報告する。
>
> ### 26.2 判断の分界（CLAUDE.md 憲法第1条〜第3条と同一）
> *   **ユーザーと協働**: ビジョン・方針・優先順位・フェーズの定義・憲法の改訂・**課金**。
> *   **Claude Code が単独で決めて実行**: フェーズ内の実装・設計・PR 分割・マージ時機・検証方法。
> *   **停止条件**: フェーズの終了条件を満たしたら止まり、ゲート報告を出して判断を待つ。次のフェーズには入らない。
>
> ### 26.3 証拠主義
> *   「完了」は主張ではなく証拠で示す（コマンドと出力・CI の run ID・成果物）。
> *   **自分の成果を自分で採点しない。** 終了条件の判定は `gate-verifier` に別コンテキストで反証させる。
> *   反証は分類する（うっかり型は塞ぐ／意図的な回避は limits に宣言）。同一条件は最大2周（正典 `verification_policy`）。
>
> ### 26.4 停止の合図
> 同じテストが3回連続で落ちる／正典と実測が食い違う／終了条件が達成不能と分かる／予算に無い有料利用が要る／大規模な並列が要る — いずれもその場で報告して止まる。
>
> 旧条文の Gemini-Opus ダブルループ・30並列×50タスク・L1〜L4 の4レベル階層・24時間連続稼働・§26.9 の Phase 5〜20 ロードマップは、
> 実体が無く CLAUDE.md の憲法と二重になっていたため削除した。品質ラチェット（旧 26.6）は §20 に吸収した。
