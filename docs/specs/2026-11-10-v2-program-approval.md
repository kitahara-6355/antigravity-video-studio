# V2: 番組化の承認の門と、実測の品質ゲート（2026-11-10）

Fable 5.2 集中計画（第2版）の V2。対象の課題は D-16・D-07・D-48・D-41・D-47・D-42・D-04。
V3〜V5 のスレッドと gate-verifier が最初に読む資料。

## 何が問題だったか

本線の承認の門（R2・`backend/revenue/approval_gate.py`）は 9 月に完成し、`vault-outputs/final`・`shorts` を守っている。
しかし 10 月の実績（久木田回 v61〜v66・Shorts 8本・サムネ）は、本線の外の道具（`backend/program_package/`）で作り、
`python -m backend.drive_layout put finished` で Drive の「40_完成」へ送っていた。**この道は門を1つも通らない。**
承認は北原さんのチャットの言葉と Drive のラベル「品質確認」にあったが、置く操作とは結びついていなかった。

## 決めた形

**置き場は Drive の 40_完成。門は「置く操作」と「置き場の点検」の2か所に置く**（R2 と同じ考え方 — 書き方ではなく結果を見る）。

| 段 | 何をするか | どこ |
|---|---|---|
| 提案 | 1件ごと（仕上げ版1本・Shorts 1本・サムネ1枚）に中身の指紋を控える。**実測の品質ゲートに通らなければ提案にならない** | `program_gate propose` |
| 承認 | 人の承認を控える。**AI の名前では承認できない**。開示（合成メディアを含むか）と根拠（どこで承認されたか）が必須 | `program_gate approve`（`--from-qc` でラベル「品質確認」から） |
| 置く | 承認済みの中身（sha256 が一致）だけが投稿する棚へ出る。1つでも未承認があれば何も送らない | `drive_layout put finished`・`drive_organize mv / rename` |
| 点検 | 40_完成 の動画と画像が、1つ残らず承認か基準線に辿れるか。**読めなければ緑にしない** | `program_gate gate`・`drive_layout audit` |

- **2つの棚**: 名前か（収録ID より下の）フォルダ名に `確認用`・`候補`・`見本` が入る物は「見てもらう物」で、承認の前でも置ける
  （承認の材料なので止めない。R2-C1 がプレビューを止めないのと同じ）。**それ以外の動画と画像はすべて「投稿する物」**
- **入れ物を列挙しない**: Drive が動画・画像と見る物すべてを問う。手元のファイルは、文章の付属物（`.txt`・`.json` など）だけを外し、
  知らない拡張子は問う側に倒す（R2 の 5 周目の教訓）
- **基準線**: 門ができる前（2026-11-10 より前）から投稿する棚にあった 11 件（v62 の本体・Shorts_投稿用の 8 本・サムネ 2 枚）は、
  Drive の id と大きさが同じ間だけ通す。承認の証拠を後から作らない
- **台帳はリポジトリ**（`backend/config/program_approvals.json`）。クラウドのコンテナは消えるので、提案と承認はコミットで残す

## 実測の品質ゲート（`backend/revenue/program_quality.py`）

ffprobe / ffmpeg / Pillow で測り、線（`backend/config/program_quality.json`）と比べる。AI は呼ばない。0円。

- 測る物: 映像の形式・色の形式（yuv420p）・大きさ・長さ・音声の有無・映像と音の長さの差・最後まで再生できるか・
  全体の音の大きさ（LUFS）・音のピーク・黒い画面・無音。サムネは形式・大きさ・ファイルの大きさ
- **点数を作らない**（項目ごとの実測値・線・合否だけ）。**測れなかった項目は合格にしない**
- 2026-11-10 に久木田回 v62 の確認用360p（42分）で実測: 11 項目中 10 項目が線の内側。
  **音のピークだけが線の外（最大 +5.8 dBFS・7:34 付近。0 dBFS 超えが 2,559 秒中 151 秒）**。
  縮小版の測定なので、本体（v62_ロゴなし.mp4）でも同じかは北原さんの PC で測る

## 守らないこと（limits — 意図的な回避は塞がない）

1. **名前で棚を分けている。**未承認の完成品に「確認用」と名付ければ 40_完成 に置ける。それは見てもらう物であって、
   投稿する棚（`Shorts_投稿用` など）には出ていない。その名前のまま YouTube に上げるのは意図した回避
2. **Drive の画面で人が直接動かす・名前を変える・アップロードする**操作は止められない。点検（`gate`・`audit`）が後から赤で捕まえる
3. **台帳を手で書き換えれば通る**（承認者・指紋を手で書く）。R2 の limits「実行記録を手で書けば通る」と同じ扱い。
   ただし提案の中身だけを差し替えた承認は数えない（`files_sha256` と比べる）
4. **「人が実際に見たか」は保証できない。**チャットの承認を Claude が控えるとき、`--by 北原` と打つのは Claude。
   根拠（`--evidence`）に日時と言葉を残して、後から突き合わせられるようにしている
5. **基準線の md5 は未記入**（2026-11-10 は Drive のコネクタで読んだため id と大きさだけ）。鍵のある所で
   `program_gate snapshot` を取り直したら md5 を足す。それまでは「同じ id・同じ大きさで中身だけ違う」差し替えは見えない
6. **文章の付属物（投稿文・チャプター・字幕）は問わない。**R2 のサイドカーと同じ扱い
7. **40_完成 の外**（30_AVS_作業・手元のフォルダ）に置いた完成品は見えない。投稿は 40_完成 から行う運用が前提
