# R2 C1〜C3 の設計 — 承認していない動画は書き出せない（2026-09-19）

> 対象: R2-C1（承認なしで書き出さない・D-41）／R2-C2（動画ごとの証跡・人の差分）／R2-C3（AI 生成の開示）。
> **C5（承認画面）は中間ゲートの後**（2026-09-19 ユーザー決定）。この設計は CLI とファイルで完結させる。

## 1. 前提の確認結果 — 土台はほぼ使えない

正典の R2 の前提「D-16 / D-07 の未実装部分が承認工程の土台として使える」を、2026-09-19 に1回動かして確かめた。

| 確かめたこと | 結果 |
|---|---|
| 承認の状態 | `ProgressiveReviewPlugin` の辞書だけ。**実走ごとに分かれず、再起動で消える** |
| 採点前の状態 | 保留中が0件になり、**何も見ていないのに全部承認済みと読める**（安全側に倒れない） |
| 本線の書き出し | coordinator は承認を**一切見ていない** |
| API | `/api/review/*` は未登録で 404（D-23） |

使えるのは段階の分け方と、段階ごとのレポートの生成だけ。**承認の記録と書き出しの門は新しく作る。**

## 2. 流れを2段に分ける

**今（D-41 の原因）**: 直列 → 並列 → **書き出し** → **品質改善ループ** → 後処理。
ループで合格しても、書き出しは不合格のときの safe モードのまま残る。

**R2 の後**:

```
① python -m backend.agents.pipeline_coordinator <素材>
     直列 → 並列 → 品質改善ループ（D-41: 書き出しの前へ）→ 提案を残す → 実行記録は awaiting_approval で閉じる
② 人がプレビューを見て、必要なら AI の出力（字幕・メタデータ）を直す
③ python -m backend.revenue.approval_gate --approve <run_id> --synthetic {yes,no} [--by <名前>] [--note ...]
     提案の写しと現物の差分を取り、承認を記録する（approval.json）
④ python -m backend.revenue.approval_gate --export <run_id>
     承認があり、提案が承認のときから変わっていないときだけ書き出す。開示をサイドカーに入れる。
     実行記録を completed / degraded で閉じ直す（export.json）
```

- `--gate`: 最新の実走について — 承認待ちなら FAIL（**書き出していない**）、承認なしで書き出していたら FAIL、
  開示が無ければ FAIL
- `--trace <run_id>`: 提案 → 承認（差分・開示の判断）→ 書き出し を並べて出す（R2-C2 の verify）

### 門の置き場所 — 書き出しの関数そのもの

CLI だけに門を置くと、画面（router）経由で書き出せてしまう。**書き出し（最終レンダリング）の直前で、その実走の
承認を確かめる**。承認が無ければ書き出しの工程は結果を返さない（R1.5-C1b により「失敗」として記録される）。

## 3. 残すもの（`output/runs/<run_id>/`）

| ファイル | 中身 | 書くのは |
|---|---|---|
| `proposal.json` | プレビュー（パスと sha256）・品質（点・採点したか・合格か）・書き出しモード（ループの後に決まる）・飛ばした機能・AI の出力の一覧（パスと sha256）・使ったモデル | ① |
| `proposal/` | AI の出力の写し（字幕・YouTube メタデータ）。**人が直す前の姿**を残す | ① |
| `approval.json` | 承認の時刻・承認した人・`proposal.json` の sha256・人が手を入れた差分（ファイルごとの unified diff）・開示の判断 | ③ |
| `export.json` | 書き出した動画（パスと sha256）・承認への参照（`approval.json` の sha256）・開示を入れたサイドカー | ④ |

**提案が承認の後に変わっていたら書き出さない**（`proposal.json` の sha256 を承認に焼き込み、書き出しの前に照合する）。

## 4. 人が手を入れた差分（R2-C2）

**書き出しが実際に使うものだけが、承認の時点で直せる。** 最終の書き出しはプレビューの再エンコード
（＋ BGM・ロゴ・音量の正規化）で、字幕と構成はプレビューに焼き込まれている（`render_worker` を読んで確かめた）。

- **直せる**: YouTube のメタデータ（タイトル・説明・タグ）。① で AI の出力を `proposal/`（直す前の姿）と
  `working/`（人が直す現物）に写す。③ が両者の差分を取り、`approval.json` に残す。
  **差分が空でも「直さずに承認した」ことが記録される**
- **直せない（差し戻して提案を作り直す）**: 字幕・構成。C1〜C3 では差し戻しの仕組みは作らない（limits に宣言）

## 5. AI 生成の開示（R2-C3）

正典の R2 の limits: 「開示ラベルの要否はコンテンツによる。**判定は人間が行う**（機械はメタデータの有無だけを見る）」。

- ③ で人が合成メディアの有無を決める（`--synthetic yes|no`。省けない）
- ④ は YouTube メタデータのサイドカーに `ai_disclosure` を入れる — 合成メディアの有無（人の判断）・AI を使った工程
  （実行記録の工程とモデルから機械的に作る）・判断した人と時刻
- **`ai_disclosure` が無ければ書き出しを止める**（④ が exit 1、`--gate` も FAIL）

## 6. R1.5 の条件を壊さない

| 条件 | 影響と扱い |
|---|---|
| C1a（記録が再開材料） | 承認待ちの記録にも工程・モデル・入力が残る。`--resume` は「承認して書き出す」手順を案内する |
| C1b（失敗を成功に数えない） | 承認待ちは completed ではない。門で止まった書き出しは失敗として残る |
| C1c（赤い実走を FAIL） | 承認待ちの実走は動画を作っていないので `artifact_gate --gate` は FAIL（**条件の文言どおり**）。書き出した後は今までどおり判定する |
| C3（AI の出力が成果物に届く） | 書き出しは承認した提案から作るので、AI の出力は今までどおり届く。`--ai-effect` は書き出した実走どうしで比べる |
| C4b（出る数字が出所を名乗る） | router の状態に承認待ちが加わると面の形が変わりうる。**変わったら台帳を査読して更新する** |

## 7. やらないこと（C1〜C3 の範囲の外）

- **承認画面**（C5。中間ゲートの後）。画面から走らせた実走も承認待ちで止まり、画面には状態だけが出る
- **議長のバイパス**（憲法 §9.3 の緊急時のスキップ）。C1 を「承認していない動画は書き出せない」の字義どおりに保つため、
  作らずに limits に宣言する
- 複数人の承認・承認の取り消し
- §9.2 の HTML レポート（Before/After の横並び）— 既存の `PreviewReportGenerator` がそのまま動くなら提案に添える。
  動かなければ C5 に回す

## 8. 検証

- 契約テストを書いたら変異を当てる（承認なしで書き出せる・提案が変わっても書き出せる・開示が無くても書き出せる、
  の各変異で落ちること）
- 実走: ダミーキーと実キーで各1本、承認して書き出すまで。`--gate`・`--trace`・`artifact_gate --gate` を確かめる
- gate-verifier に C1〜C3 を判定させ、**中間ゲート**でユーザーに報告する（C5 に進むか、R3 を先にするか）
