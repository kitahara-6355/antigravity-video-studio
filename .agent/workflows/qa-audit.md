## 2. 機能実効性検証 (FV: Functional Verification) — v2.0新設

> **テストのためのテストを禁ずる。** 全FVは「ユーザーが使って違和感がないか」を検証する。

### 2.1 FV検証テーブル

自動編集機能ごとに、実用品質を検証する。対象Workerの実装完了後に必ず実行する。

| ID | 機能 | 検証名 | 合格基準 | 検証方法 |
|:---|:---|:---|:---|:---|
| FV-01 | 文字起こし | 精度検証 | WER ≤ 15% (日本語) | Whisper出力 vs 手動比較 |
| FV-02 | 文字起こし | セグメント品質 | start/endが実音声と±0.5秒 | FFmpegで抜粋再生+聴覚確認 |
| FV-03 | 文字起こし | 処理時間体感 | 5分動画で180秒以内 | 実動画タイマー計測 |
| FV-04 | AI校閲 | 修正妥当性 | 不要修正率 ≤ 10% | 10seg手動判定 |
| FV-05 | AI校閲 | 固有名詞辞書効果 | 辞書語の修正成功率100% | 辞書付きテスト |
| FV-06 | AI校閲 | 行分割品質 | 1行18文字以下遵守率100% | 全seg検査 |
| FV-07 | SmartCut | カット品質 | 重要シーン保持率 ≥ 90% | マーク済みsegの保持率 |
| FV-08 | SmartCut | 時系列整合性 | カット後の自然な流れ | ブラウザ再生+目視確認 |
| FV-09 | SmartCut | 目標尺精度 | 目標尺の±10%以内 | duration計測 |
| FV-10 | プレビュー | 画質十分性 | 字幕が判読可能 | Browser Agentスクリーンショット |
| FV-11 | プレビュー | 再生可能性 | MP4として正常再生 | ブラウザ再生確認 |
| FV-12 | 品質ゲート | スコア信頼性 | 手動評価との相関 ≥ 0.7 | 5動画の比較 |
| FV-13 | 品質ゲート | 改善アクション有効性 | 改善後スコア ≥ 改善前 | 前後差分 |
| FV-14 | レンダリング | 音声品質 | BGMダッキングで台詞聞取 | 聴覚確認 |
| FV-15 | レンダリング | 字幕焼込品質 | 判読可能+位置適切 | サンプルフレーム |
| FV-16 | レンダリング | ロゴ表示品質 | 位置/透明度が適切 | サンプルフレーム |
| FV-17 | レンダリング | ラウドネス基準 | -16±2 LUFS | FFprobe計測 |
| FV-18 | YouTube最適化 | タイトル品質 | 30-60文字, SEOキーワード | 手動チェック |
| FV-19 | YouTube最適化 | タグ品質 | 5-15個, 重複なし | 自動チェック |
| FV-20 | YouTube最適化 | チャプター精度 | 時刻がseg境界と±3秒 | 自動チェック |

### 2.2 FV実行手順

1. 対象Workerのテスト動画(TV-01)を用意する
2. パイプラインを当該Workerまで実行する
3. FVテーブルの対応行を検証する
4. 不合格の場合→修正→再検証（合格まで繰り返す）
5. **FVレポート**を作成し保存する

```markdown
## 検証結果

|:---|:---|:---|:---:|
| FV-XX | ... | ... | ✅/❌ |

## 不合格項目の是正
| ID | 原因 | 修正内容 | 再検証結果 |
|:---|:---|:---|:---:|

## 結論
→ [Worker名]は実用レベルの品質を達成 / 未達成
```

## 3. UXストーリー駆動ブラウザE2E — v2.0新設

> **「UIUXストーリーを満たしたとき、機能は完成」。ゴール数ベースではなくUXストーリー充足ベースで判定する。**
> テストのためのテストは禁じ、ゴールは全て実ユーザー操作から導出する。

### 3.1 事前準備: UXストーリー更新

当該自動編集機能の実装完了後、E2Eテスト実行**前**に:

1. `PROJECT_CONSTITUTION.md` §7.3 のUXストーリー(O-1〜O-12, A-1〜A-7)を確認
2. 当該機能に関連するUXストーリーが最新の実装を反映しているか検証
3. 必要ならUXストーリーを更新し、`USER_MANUAL.md` §3.2と同期
4. **[必須]** `.agent/ux-verification-rulebook.md` §3 の6ステップを実行:
   - Step 1: 憲法UXストーリー確認
   - Step 2: `ux_verification/stories/{ux_id}_*.json` を更新 (シーン+検証項目)
   - Step 3: ラチェット検証 `pytest tests/test_ux_ratchet.py -v` → 全PASS必須
   - Step 4: E2Eテスト更新 (5層モデル: L1 DOM/L2 視覚/L3 操作/L4 状態/L5 E2E)
   - Step 5: スナップショット保存 `ux_verification/snapshots/v{N}.json`
   - Step 6: 充足マトリクス+VERIFIED_FACTS更新

### 3.2 UXストーリー→E2Eゴール導出

各UXストーリーから「ブラウザ上で確認可能な期待動作」を具体的ゴールとして記述する:

| UXストーリー | E2Eコンポーネント | ゴール導出例 |
|:---|:---|:---|
| O-1: フォルダ別RAW選択がワンクリック | ProductionPipeline | フォルダアイコン→ファイルリスト→選択→処理開始 |
| O-4: 尺調整はスライダードラッグ | SmartCutPanel | スライダードラッグ→推定尺リアルタイム更新→確定 |
| O-6: 品質80点未満は自動改善 | QualityGate | 低品質入力→スコア<80→改善提案表示→適用→再評価 |

### 3.3 ブラウザE2Eテスト実行

```
事前: UXストーリー更新済み + E2Eゴールシート準備済み
  ↓
① Browser Agent がゴールシートに沿ってUIを操作
  ↓
② スクリーンショットを収集し差分分析レポートを作成
  ↓
③ UXストーリー × E2Eゴールの充足マトリクスを更新
  ↓
④ 未充足のUXストーリーがある?
   ├── Yes → コード/UI修正 → ①に戻る
   └── No → 機能完成判定 ✅
```

### 3.4 完了判定基準

```
完了 = 以下の全てを満たす:
  □ 当該機能の全UXストーリーの全E2Eゴールが PASS
  □ FV(機能実効性検証)の全項目が PASS
  □ /vision-gap-audit の当該§条項の乖離が 0件
  □ 差分分析レポートが保存済み
```

### 3.5 差分分析レポートテンプレート

```markdown

## UXストーリー充足マトリクス

|:---|:---|:---:|:---|
| O-XX: [内容] | G-XX〜G-XX | ✅/❌ | |

## E2Eテスト詳細
| ゴールID | 期待動作 | 実際の動作 | スクリーンショット | 判定 |
|:---|:---|:---|:---|:---:|

## 憲法乖離チェック
| §条項 | 乖離 | 対応 |
|:---|:---:|:---|

## 結論
→ [機能名]は全UXストーリーを充足 / 未充足(残: N項目)
```
