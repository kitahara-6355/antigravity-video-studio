## 1. Executive Summary: What is Antigravity?

**Antigravity Video Studio** is not just a video editing tool; it is a **"Resonant Creative Ecosystem"** where human intent and AI execution merge.

Conventional tools (Adobe Premiere, DaVinci Resolve) focus on "Editing Efficiency."
Antigravity focuses on **"Creative Velocity"**—the speed at which a thought becomes a reality.

By introducing a **Multi-Agent Trinity System**, it separates the "Operator" burden from the user, allowing them to function solely as a "Director" and "Strategist." Furthermore, with the **Phase 18 Update**, it has evolved into a **"Collaborative Studio"** that seamlessly connects technical administrators (Admin) and intuitive creators (Channel Owner), enabling a highly efficient family-based production workflow.

## 2. Core Philosophy: The Trinity & The Duo

### 2.1 The Trinity System (Human-AI Resonance)
The system is built on the philosophy that AI should be more than a tool; it should be a specialized team.

*   **User (Chairman)**: The decision-maker. Holds Veto Power and The Gavel.
*   **Nexus (Dispatcher)**: The semantic router that translates vague human intent into specific agent commands.
*   **The Council (Agents)**:
    *   **Strategist**: Guardian of the Brand Constitution. Ensuring long-term consistency.
    *   **Director**: Creative lead for visuals and rhythm.
    *   **Analyst**: Data-driven advisor for objective quality control.

### 2.2 The Duo Principles (二人三脚の儀)
A unique operational protocol designed for "Tech-savvy Children (Admin)" supporting "Creative Parents (Owner)."

*   **Role Definition**:
    *   **Admin**: Handles prompt engineering, system stability, and final approval.
    *   **Owner**: Focuses purely on "Like/Dislike" intuition (One-tap Feedback).
*   **Hierarchical Decision**: Owner's intuition guides the draft; Admin's logic secures the final product.

## 3. System Architecture & Technical Innovation

### 3.1 Stack Overview
*   **Frontend**: React + Vite (SPA). A dual-interface design ("Writer's Desk" vs "Director's Desk") to reduce cognitive load.
*   **Backend**: Python (FastAPI). Async architecture handling heavy video processing and LLM reasoning concurrently.
*   **AI Core**: `google-genai` (Gemini 2.0 Flash Exp). Using structured JSON output for strict control over non-deterministic LLM behavior.

### 3.2 Key Mechanisms (Micro-Innovations)

#### A. Semantic Dispatching (Nexus)
Instead of hard-coded command buttons, the system uses an LLM-based router (`Nexus`) to interpret natural language inputs. It dynamically assigns tasks to the most relevant agent (e.g., "Make it pop" -> Director Agent).

#### B. Smart Cut Engine
A rule-based + AI hybrid engine that recursively analyzes audio waveforms to remove silence and fillers *before* the user even sees the timeline. This removes 90% of the "tedious" work instantly.

#### C. Operational Excellence Modules (Phase 18)
*   **Project Archiver**: Automatically creates snapshots before every critical action (Render/Save). Allows "Time Travel" to previous states, enabling fearless experimentation.
*   **Quality Gate Agent**: A dedicated "QA Director" agent that scans the script and subtitles before rendering. It checks for:
    *   Reading speed (rhythm)
    *   Brand consistency
    *   Logical contradictions
    *   Typos and forbidden terms
    *   *If the score is below 80, rendering is blocked with constructive feedback.*

## 4. User Experience Flow (The "Duo" Workflow)

### Step 1: Ingestion & Analysis
*   **User**: Uploads raw footage and whispers a vague theme (e.g., "Peaceful morning routine").
*   **System**: Nexus analyzes the request, Strategist aligns it with `constitution.json`, and Director generates a draft cut plan.

### Step 2: Collaborative Tuning
*   **Director Agent**: Proposes BGM, color grading, and subtitle rythym on the **Collaborative Panel**.
*   **Owner (Mom)**: Views the simplified panel on a tablet. Taps "Like" or "Dislike". No technical jargon needed.
*   **System**: Captures the feedback. If "Dislike", it asks "Why?" (optional) or tries a different "vibe" based on learned preferences.

### Step 3: Journaling & Evolution
*   **System**: Records the decisions in the `Project Journal`.
*   **Soul Narrative**: Updates the user model. "Owner prefers piano over guitar for emotional scenes." The system *learns* the user's taste over time.

### Step 4: Quality Gate & Render
*   **Admin**: Presses "Render".
*   **Quality Gate**: "Wait! Segment 4 is too fast to read. Fix?"
*   **Admin**: "Auto-fix it." -> System adjusts duration. -> Render proceeds.
