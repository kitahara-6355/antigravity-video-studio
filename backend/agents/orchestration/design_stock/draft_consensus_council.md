# 設計ドラフト: 分散型エージェント協議体 (Council Graph) および魂のドキュメント保護設計 (IMP-CONCIL)

## 概要
複数の役割を持つサブエージェント（レビュー、監査）が実装コードを相互査読し、合意形成を行ってから自動マージする仕組みの設計ドラフト。また、日本語で記された「魂のドキュメント（憲法・ビジョン・UXストーリー）」を機械的破壊から守る絶対防御ルールを定義する。

## 1. 協議会 (Council) の役割定義
- **Flash (実装者)**: タスクに基づきコードを変更し、テストをPASSさせる。
- **Reviewer Agent (設計査読者)**: `implementation_plan.md` や `GEMINI.md` に適合しているか、無駄な負債を含んでいないかを査読。
- **Auditor Agent (安全監査者)**: 規約違反（print、bare except）や、ドキュメント保護規則の違反を検出。

## 2. デッドロック（無限ループ）の回避ルール (エスカレーション)
- Flash と Reviewer 間の差し戻し修正が **最大3往復** に達しても合意（LGTM）が得られない場合、タスクのステータスを `Awaiting Opus`（保留）とし、マージをブロックして本セッション（Opus）および人間（ユーザー）の判断へ自動エスカレーションする。

## 3. 魂のドキュメント不磨不滅（Read-Only & Append-Only）ルール
- **保護対象**: `PROJECT_CONSTITUTION.md` (憲法), `VERIFIED_FACTS.md` (決定事実), `ux-verification-rulebook.md` (UXストーリー規則) を含む、すべての日本語 Markdown ドキュメント。
- **編集時の厳格な追記ログ形式 (Append-Only Log Format) 義務化**:
  - 既存の文章を書き換えたり、削除したりすることはシステム的に全面的に禁止（Read-Only）とする。
  - 新たな事実や決定を追記する場合は、ファイルの末尾に `### [YYYY-MM-DD HH:MM] タイトル` などのタイムスタンプ付きヘッダーを作成し、新しい段落として追記する形式のみを許可する。
- **Git差分の自動監査 (Auditorによる検証)**:
  - コミット前の `git diff` において、保護対象ファイルに `deletions`（削除行）が含まれている場合、またはファイル末尾以外への `insertions`（追加行）がある場合、コミットを無条件で拒否（Reject）する。
