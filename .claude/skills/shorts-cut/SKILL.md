# 対談の完成版から Shorts を切り出す（番組化の2段目）

2026-10-23 に「20250922_久木田ヒロノブ」で Claude Code が8本を作り、北原さんが全部を出すと決めた手順。
番組化はまず Claude Code で作り切り、スキルにしてから GWS の Gemini Spark で再現する（北原さんの方針）。
手順は**ファイルとコマンドだけ**で書いてある。どの AI が動かしても同じ mp4 が出る。

- 費用は0円。Gemini API も AI 画像・音声の生成も使わない（絵も声も収録のまま。合成でないので開示ラベルは要らない）
- 場面選びとキャッチ（手順1）だけは AI が字幕を読んで考える。**動かしている AI 自身が読む**（API を呼ばない）
- 投稿は北原さんがする。AI は投稿しない（外に出す操作なので）

## 入力

| もの | 場所 | 使い道 |
|---|---|---|
| 承認済みの字幕 | Drive `40_完成/<収録ID>/` の `.subtitles.json` | 場面を選ぶ・Shorts に焼き込む |
| 編集の固定（lock） | Drive `30_AVS_作業/収録/<収録ID>/再現_*/assets/*.lock.json` | 完成版の時刻 → raw の時刻 |
| つないだ raw | lock の `material`（例 `raw4_concat.mp4`）。無ければ `interview-edit` の結合で作る | 絵と音。**完成版は字幕が焼き込まれているので使わない** |
| フォント | `python -m backend.program_package.thumbnail --fetch-fonts`（Google Fonts・OFL。初回だけ） | キャッチ（しっぽり明朝 B1 の 800）・字幕（Noto Sans JP Black） |

## 手順

### 1. 場面を選び、キャッチを2行で書く（AI が字幕を全文読む）

長尺から、**それだけ見ても面白い**場面を6〜10本選ぶ。基準:

- **ひと言で言える山がある**: 実績（鬼滅の刃のフォント）・失敗談（テイク23）・格言（考えながら書かない）・意外な事実（デビューのギャラは菓子折り）
- **60秒以内**。字幕の区切りに合わせると延びるので、区間を書いたら長さを必ず確かめる
- 話の途中から始めない。**字幕の出だしで始まり、字幕の終わりで終わる**
- 長い話は2区間をつないでよい（例 テイク23: 折れる → 芯を替えたら折れない）
- 揮毫のように字幕の無い場面は**秒の数**で書き、**書き終わった瞬間**で切る（S5 は43.4秒）
- キャッチは山を2行で。1行目が赤（引き）、2行目が金（答え）。本編で言っていないことは書かない

指定ファイル `backend/config/shorts/<収録ID>.json` に書く（見本 `examples/20250922_久木田ヒロノブ.json`）:

| 欄 | 中身 |
|---|---|
| `recording` / `lock` / `names` | 収録ID・lock の場所・出演者名（北原さんが決めた表記のまま） |
| `background` | 背景の明るい色と暗い色。**決まり: 明るい薄紫** `light [246,232,240]` / `deep [176,136,162]` |
| `frame` | 絵の囲み。**決まり: `inset 40`・`width 14`・`shadow true`**（金の額縁で四方を囲む） |
| `clips` | `key`（S1…）・`title`（2行）・`parts`（区間。`"m:ss"` は字幕の出だし、数は秒） |
| `post_order` | 北原さんが決めた投稿の順番とペース（決まってから書く） |

時刻はすべて**完成版の時刻**。道具が lock をたどって raw の時刻に直す。

### 2. 書き出す

```
python -m backend.program_package.shorts SPEC.json --raw RAW.mp4 --subs SUBS.json --out OUT [--only S1 S3]
```

1本あたり約30秒（CPU）。でき上がりは `OUT/<収録ID>_<key>.mp4`。画面の作り:

- 上: キャッチ2行（赤と金の明朝。長い行は左右60pxの余白まで自動で縮む）と出演者名
- 中: 対談の絵を金の額縁で囲み、下に影
- 下: 承認済みの字幕（白・Noto Sans JP Black 66）。**下 1/3 と右端は Shorts の操作ボタンが重なる**ので何も置かない

### 3. 確かめる

- 長さ: `ffprobe -v error -show_entries format=duration -of csv=p=0 <mp4>` が **60 以下**
- 1本ずつ10秒目のコマを出して、キャッチがはみ出していないか・字幕が額縁と重ならないかを見る

  ```
  ffmpeg -v error -ss 10 -i <mp4> -frames:v 1 -vf scale=540:-1 -y check.jpg
  ```

- 出だしと終わりが言葉の途中で切れていないか（字幕の最初と最後の1枚を読む）

### 4. 北原さんに選んでもらう

- 分かりやすい名前に写して（例 `Shorts_S1_鬼滅の刃.mp4`）、Drive `40_完成/<収録ID>/Shorts候補_<案>/` に置く:

  ```
  python -m backend.drive_layout put finished <フォルダ> --to "<収録ID>/Shorts候補_<案>"
  ```

  北原さんはスマホで見るので、返信には**ファイルごとの Drive のリンク**と長さを並べる
  （スレッドの添付は1回6件・1スレッド24件まで）
- 決めてもらうこと: 出すもの・順番・ペース。決まったら指定ファイルの `post_order` に控える

### 5. 投稿用フォルダにまとめる（2026-10-25 北原さん: Shorts を先に仕上げる）

指定ファイルの `posts` に1本ずつ `title`・`body`・`tags`・`label` と、共通の `footer`（本編への誘導）・`tags` を書く。
本編で言っていることだけを書く。本編の URL は公開後に `main_url` へ入れる（それまでは【本編の公開後に URL を入れる】と出る）。

```
python -m backend.program_package.shorts_kit SPEC.json --rendered <書き出したフォルダ> --out <投稿用フォルダ>
```

- `01_S1_鬼滅の刃.mp4` のように**投稿の順番の番号**を付けて写す（中身は変えない）。`投稿文.txt` に順番どおりのタイトル・説明・ハッシュタグ
- **60秒を超える1本があると止まる**（2026-10-25 に S2 が60.2秒だったので詰めた）。投稿文の漏れ・タイトル100字超え・タグの重なりも止まる
- Drive `40_完成/<収録ID>/Shorts_投稿用/` へ（`drive_layout put finished <フォルダ> --to "<収録ID>/Shorts_投稿用"`）
- 投稿は北原さんが手で行う

## おすすめの出し方（2026-10-23 の判断の根拠）

- 質が揃っていれば**本数は多いほうが登録者を集めやすい**ので、作った候補は基本すべて出す
- 週2〜3本。**一番強い実績の1本を先頭**に、次に絵で引く1本（揮毫）、残りは話の面白さ順
- 長尺の公開に合わせて、Shorts の概要欄か固定コメントで長尺へ誘導する

（YouTube の仕様・推奨は二次情報。投稿前に一次情報と突き合わせる）
