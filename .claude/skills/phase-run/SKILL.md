# フェーズ自律実行

human-on-the-loop の実行側。**フェーズの中は自分で決めて動く。フェーズの境界で止まる。**

## 前提

- 正典は `antigravity-video-studio/backend/branding/vision_backlog.json` の1つだけ
- `phase_state.json` と `docs/BACKLOG_MASTER.md` は**参照資料**。正典ではない
- `.agent/` と `GEMINI.md` は Antigravity 側の資産。**読むのは自由、書かない**

## 手順

### 1. 現在地を確定する

正典から `current_phase` と `exit_criteria` を読む。

**ここで食い違いを見つけたら、実装より先に正典を直す。** 現在地が曖昧なまま
自律実行すると、終わっていないものを終わったことにするか、
終わったものを延々やり直す。どちらも人間が気づくまで止まらない。

### 2. 終了条件から逆算して作業を選ぶ

`exit_criteria` のうち `met: false` のものだけが作業対象。
**条件に紐づかない改善は、目に付いても今はやらない** — バックログに積む。

優先順位は「軸の重み × 改善余地」。正典の `axis_scores` に重みがある。

### 3. `/goal` を張る

そのフェーズの終了条件を `/goal` の条件文にする。毎ターン別モデルが成立を
判定し、成立するまで自動で次のターンに入る。

条件は**会話に出てきたもので判定される**（評価器はファイルを読まない）。
「テストが通る」ではなく「`pytest backend/tests/test_x.py` が exit 0 で終わり、
その出力が会話に出ている」と書く。

### 4. PR 単位で潰す

1つの終了条件 = 1つ以上の PR。**1 PR は1つの理由で説明できる大きさまで。**

- ブランチは `cc/` 接頭辞
- `gh pr merge <N> --merge --auto` で auto-merge を予約し、**CI を待たずに次へ進む**
- BEHIND になったら `gh pr update-branch` を**1本ずつ**。複数同時に追随させると
  CI を余計に消費する
- PR を出したら **1行だけ**報告する（「何を・なぜ・検証結果」）。それ以上は書かない

### 5. 変更は必ず突き合わせで検証する

`origin/main` の worktree と**同じテスト集合**を走らせ、失敗集合が一致することを見る。
一致しなければ自分の変更が原因。

    PYTHONPATH=./backend GOOGLE_API_KEY=dummy_key_for_ci python -m pytest <files> -q --no-cov

env を付け忘れると両側とも収集エラーで落ち、「差分ゼロ＝退行なし」に見える。

### 6. 停止する

終了条件が全部 `met: true` になったら**そこで止まる**。次のフェーズには入らない。
`/gate-report` を実行してゲート報告を出し、人間の判断を待つ。

## 止まるべき合図

以下は自律実行を続けずに**その場で報告して止まる**。

- 同じテストが3回連続で落ちる（CLAUDE.md の既定ルール）
- 正典と実測が食い違い、どちらが正しいか判断できない
- 終了条件そのものが達成不能だと分かった（条件の定義はユーザーの領分）
- **課金を伴う操作が必要になった**（憲法第3条）。1円でも請求されるものはすべて。
  このリポジトリで一番踏みやすいのは **Gemini API** — パイプラインを1回走らせるだけで課金される。
  テスト実行は無料（`net_guard` + ダミーキー）
- 大規模な fan-out（workflow / エージェント並列）が必要だと判断した

## やってよいこと（都度確認しない）

実装方式・PR 分割・マージ時機・リファクタの範囲・テストの書き方・
ブランチ運用・テスト生成物の `git checkout` による復元。事後にまとめて報告する。
